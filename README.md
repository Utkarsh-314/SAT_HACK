# SignConnect

SignConnect is a web application for account access and video meetings,
with a frontend and a FastAPI backend. This README describes the project
structure visible in the supplied VS Code screenshots. Where a file's
exact implementation is not visible, its role is described from its
filename and normal project conventions; check the source code to
confirm the precise behavior.

## 2. Backend: `BackEnd/`

The backend is the server-side part of SignConnect. It is expected to
receive HTTP requests from the frontend, perform authentication and
database operations, and coordinate real-time meeting/signaling
connections.

  ------------------------------------------------------------------------
  File or folder                      Purpose
  ----------------------------------- ------------------------------------
  `main.py`                           FastAPI application entry point.
                                      Typically creates the FastAPI app,
                                      configures middleware such as CORS,
                                      and registers the route modules.
                                      Start the backend from this
                                      directory with Uvicorn.

  `database.py`                       Database connection and setup code.
                                      Usually defines the database
                                      client/engine, session or connection
                                      helpers, and possibly model/base
                                      configuration.

  `security.py`                       Authentication and security helpers,
                                      such as password hashing, password
                                      verification, and token
                                      creation/validation. The exact
                                      functions depend on its
                                      implementation.

  `requirements.txt`                  Python dependencies needed by the
                                      backend. Install them into the
                                      virtual environment with
                                      `pip install -r requirements.txt`.

  `.env`                              Local environment configuration,
                                      such as database connection details,
                                      secret keys, and other settings.
                                      Keep real credentials private.

  `routes/`                           FastAPI route modules. Separating
                                      routes by feature keeps `main.py`
                                      smaller and organizes API endpoints.

  `routes/__init__.py`                Marks `routes` as a Python package;
                                      it may also expose/import route
                                      modules if written to do so.

  `routes/auth.py`                    Expected to contain account-related
                                      endpoints, such as signup, signin,
                                      and authentication checks.

  `routes/meetings.py`                Expected to contain meeting-related
                                      HTTP endpoints, such as creating or
                                      joining a meeting and retrieving
                                      meeting information.

  `routes/signaling.py`               Expected to handle real-time
                                      signaling endpoints, commonly
                                      through WebSockets, to exchange
                                      connection setup messages between
                                      meeting participants.

  `services/`                         Backend service/helper layer for
                                      reusable application logic that is
                                      not itself an HTTP route.

  `services/__init__.py`              Marks `services` as a Python
                                      package.

  `services/connection_manager.py`    Expected to manage active real-time
                                      connections, for example tracking
                                      WebSocket connections by
                                      meeting/room and forwarding messages
                                      to participants.

  `venv/`                             Local Python virtual environment
                                      containing the project's installed
                                      packages. It is machine-specific and
                                      should not be uploaded to GitHub.

  `__pycache__/`                      Automatically generated Python
                                      bytecode cache directories. They can
                                      be regenerated by Python.
  ------------------------------------------------------------------------

### How the backend files fit together

1.  Uvicorn starts `main.py`, which creates the FastAPI application.
2.  `main.py` registers the routers from `routes/` (the exact
    registration must be confirmed in `main.py`).
3.  The frontend sends account requests to the authentication routes in
    `routes/auth.py`.
4.  Authentication routes can use `database.py` for persistent user data
    and `security.py` for password/token operations.
5.  The frontend uses meeting routes in `routes/meetings.py` for
    meeting-related HTTP actions.
6.  For real-time meeting setup, the frontend connects to the signaling
    endpoint in `routes/signaling.py`.
7.  The signaling route can use `services/connection_manager.py` to keep
    track of connected participants and relay signaling messages.

## 4. How the frontend and backend connect

At a high level, the application is intended to work like this:

``` text
                         USER'S BROWSER
                               |
                 Opens FrontEnd HTML pages
                               |
             +-----------------+-----------------+
             |                 |                 |
          index.html        signin.html        signup.html
             |                 |                 |
          style.css         auth.js            auth.js
                               |
                         HTTP API requests
                               |
                               v
                    FASTAPI BACKEND SERVER
                           main.py
                               |
                    Registers API routers
                               |
             +-----------------+------------------+
             |                 |                  |
          auth.py          meetings.py        signaling.py
             |                 |                  |
       security.py       meeting logic     connection_manager.py
             |                                    |
         database.py                       WebSocket connections
             |
       Shared database
```

The diagram shows the likely responsibility flow based on the filenames.
The actual endpoint paths, database technology, and exact
JavaScript-to-route mappings must be verified from the source code.

### Typical user flows

**A. Sign up** 1. A user opens `signup.html`. 2. The page's JavaScript
(likely `auth.js`) reads the form data. 3. The browser sends a request
to the backend authentication API. 4. The backend authentication route
validates the input and uses the database layer to save the account. 5.
Security helpers should hash the password before it is stored. The
backend returns a success or error response. 6. The frontend displays
the result or redirects the user.

**B. Sign in** 1. A user opens `signin.html`. 2. The frontend sends the
submitted credentials to the authentication API. 3. The backend looks up
the account and verifies the password using the security helpers. 4. The
backend returns the configured authentication result, such as a token or
session response. 5. The frontend handles that response and navigates
the user as implemented in the JavaScript.

**C. Join a meeting** 1. The user opens the meeting/room flow in the
frontend. 2. The frontend may call `meetings.py` to create or validate a
meeting. 3. The browser connects to the signaling endpoint in
`signaling.py`. 4. The signaling route uses the connection manager to
track participants and relay signaling messages. 5. The browser clients
use those messages to establish their peer-to-peer media connection if
WebRTC is implemented in the frontend.

**Important:** Signaling exchanges connection information; it is not
necessarily the service that carries the audio/video itself. In a
typical WebRTC design, media travels peer-to-peer or through a media
server, while the backend coordinates connection setup. Confirm the
actual implementation before relying on this description.

## 5. Local development setup

### Backend

Open PowerShell:

``` powershell
cd D:\projects\SATHACK\BackEnd

# Activate the existing virtual environment
.\venv\Scripts\Activate.ps1

# If PowerShell blocks script activation, use this for the current terminal:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1

# Install dependencies
pip install -r requirements.txt

# Start FastAPI
uvicorn main:app --reload
```

The backend will commonly be available at `http://127.0.0.1:8000` if the
application uses Uvicorn's default host and port. FastAPI's interactive
API documentation is commonly at `http://127.0.0.1:8000/docs`.

### Frontend

Open the `FrontEnd` folder in VS Code and use the Live Server extension
to serve the relevant HTML page, or use the frontend hosting method
configured by the project. Do not assume that opening an HTML file
directly is equivalent to serving it over HTTP.

### Frontend API address

Check the JavaScript files for the backend base URL (for example,
`http://127.0.0.1:8000`). When other people access the frontend from
their own devices, `127.0.0.1` points to each visitor's own device, not
your computer. For a temporary shared-server setup, the frontend must
use an address reachable from those visitors, and the backend must be
exposed safely with the required CORS and network configuration.
